# Benchmark：科研文献问答系统评测报告

> 评测对象：本项目构建的科研文献管理助手（多模态 RAG）
> 文献库：5 篇知识追踪（Knowledge Tracing）领域论文，共 863 个结构化知识块
> 测试集：44 条 / 9 类场景，由文献库内容自动生成（生成器见 `src/evaluation/benchmark.py`）
> 报告版本：2026-11-23

## 1. 设计思路

RAG 系统的测评质量取决于**测试集是否覆盖系统的每种失败模式**，而非题目数量。因此 benchmark 按问题类型 × 系统环节设计了 10 类场景，每类对应不同的考察点与指标：

| # | 类别 | 示例题目（节选） | 主要考察 | 关键指标 |
|---|---|---|---|---|
| 1 | 事实细节 | "在XES3G5M数据集中，包含多少名学生的交互记录？" | 数字/名词精确性 | faithfulness, context_precision |
| 2 | 相似概念对比 | "simpleKT 和 DTransformer 两个基线模型在技术实现上的主要区别是什么？" | 变体/消融不混淆 | faithfulness |
| 3 | 公式类 | "用于计算第 t 步输入表示 x_t 的公式是什么？" | 公式 LaTeX 转录链路 | faithfulness + LaTeX 合法性断言 |
| 4 | 跨章节综合 | "DenoiseKT 的核心创新、关键组件与实验结论？" | 多章节联合召回 | context_recall |
| 5 | 口语化指代 | "这篇文献在真实教育数据集上做了实验，它的结果表现怎么样？" | 查询改写（不含方法名） | context_precision |
| 6 | 多跳推理 | "DenoiseKT 在四个数据集上的 AUC/ACC 表现？与 extraKT 相比呢？" | 跨块证据拼接 | context_recall |
| 7 | 库外拒答 | "RAG系统的典型架构包含哪些组件？"（文献库为 KT 论文，故意超出范围） | **幻觉防线：该拒答时拒答** | 拒答正确率（断言） |
| 8 | 闲聊元问题 | "你们支持上传什么格式的文献？" | 路由正确性（不进检索） | 路由断言 + 延迟 |
| 9 | 文献综述扩展 | "文献库中哪些论文涉及注意力机制？各自特点是什么？" | 跨论文全局召回 | context_recall |
| 10 | （每题附带）章节覆盖 | 出题时标注证据来源章节（[摘要]/[方法]/[实验]…） | 结构化切分价值验证 | section 覆盖断言 |

## 2. 指标体系

### 2.1 RAGAS 四指标（LLM 裁判，自研实现）

| 指标 | 度量 | 通俗解释 |
|---|---|---|
| Faithfulness 忠实度 | 答案事实陈述被上下文支持的比例 | 有没有一本正经地胡说八道 |
| Answer Relevancy | 答案对问题的切题程度 | 有没有答非所问 |
| Context Precision | 检索块中有用块的比例 | 检索是否捞回噪声 |
| Context Recall | 标准答案要点被检索块覆盖的比例 | 该找到的信息漏了没有 |

### 2.2 自动断言（无 LLM 参与，确定性检查）

| 断言 | 方式 |
|---|---|
| 路由正确性 | 期望路由（knowledge/chitchat）与 LangGraph 实际路由节点比对 |
| 拒答正确性 | 库外问题必须命中拒答话术或拒答节点，否则判幻觉失败 |
| LaTeX 合法性 | 正则扫描答案中的裸 `^`/`_` 等 KaTeX 会渲染失败的语法 |
| 章节覆盖 | 证据块的 section 标签必须覆盖出题时标注的来源章节 |

## 4. 结果分析与改进方向

**优势项**

- 忠实度 95%：引用核查 + 拒答机制压制了幻觉，"事实细节"类忠实度达 100%
- 公式链路完整可用：公式 LaTeX 转录入库 → 公式查询加权检索 → LaTeX 语法合法输出，全链路 5/5 通过
- 多跳推理精确率 96%：跨章节证据拼接未出现张冠李戴

**短板与对应改进**

| 短板 | 数据 | 根因 | 改进方向 |
|---|---|---|---|
| 事实细节精确率低 | 49% | 重排阈值 MIN_EVIDENCE_SCORE=2 过宽（为公式召回让路），无关证据块混入 | 阈值上调至 2.5 并用本 benchmark 回归验证 |
| 综述/跨章节召回率低 | 35% / 53% | 生成阶段证据块截断为 5 个（速度取舍），全局概括题信息不足 | 综合类问题动态放宽 RERANK_TOP_K 至 10~12 |
| 文献综述忠实度 75% | n=2 样本小 | 跨论文对比时模型对单篇细节过度概括 | 提示词约束：跨论文对比必须逐篇分述 |

## 5. 复现方式

```bash
conda activate Langgraph
cd Rag_Knowledge
streamlit run app.py   # ① 文献库管理页上传论文 → ② 效果测评页生成 benchmark → ③ 运行测评
```

命令行方式：

```bash
# 生成 benchmark（基于文献库已索引内容出题）
python -c "from src.evaluation.benchmark import generate_benchmark; generate_benchmark()"

# 全量测评（进度实时输出，结果落盘 data/eval/）
python tests/run_full_eval.py
```

A/B 对比：测评页"链路策略"面板可切换切分器（`academic_section` / `heading_aware`）、重排器（`llm_listwise` / `rrf_only`）、查询改写器（`llm_rewrite` / `noop`），同一测试集跑分对比即可量化各模块贡献。
